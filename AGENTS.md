# Правила для ИИ-агентов (Kimi Code, Claude, Copilot и др.)

> **Главное правило: человек — главный. ИИ — помощник.**  
> Если инструкции ниже противоречат прямому указанию автора (участника) или координатора, приоритет у указания человека.

Этот документ описывает, как нейросетям можно работать с репозиторием статьи OSTIS-2026. Он написан в первую очередь для людей; ИИ-агенты используют его как ограничивающий контекст.

---

## 1. Область, в которой разрешено работать

Каждый участник имеет **ровно один** файл в `drafts/`:

| Автор | Файл |
|-------|------|
| Глеб | `drafts/gleb_intro_scada.tex` |
| Юра | `drafts/yura_standards.tex` |
| Дима | `drafts/dima_neuro.tex` |
| Женя | `drafts/zhenya_plcnext_pid.tex` |
| Давид | `drafts/david_final.tex` |

**Разрешено редактировать:**
- свой файл в `drafts/*.tex`;
- рисунки в `figures/`, но только **новые** файлы с префиксом автора (`<автор>_<смысл>.png`).

**Запрещено редактировать (даже «немного» или «для порядка»):**
- чужие файлы в `drafts/`;
- корневой `main.tex`;
- файлы `.cls`, `.sty`;
- `.github/CODEOWNERS`, `.github/workflows/*.yml`;
- `bib/links.bib`, кроме случаев, когда агент работает **от имени Давида** и получил на это явное разрешение.

---

## 2. Что агент может делать

- Переформулировать предложения, сокращать длинные списки, заменять общие обороты научным языком.
- Следовать [`STYLEGUIDE.md`](./STYLEGUIDE.md): единая терминология, структура предложений, цитирование, оформление рисунков.
- Предлагать новые источники, но **не вставлять их напрямую в `bib/links.bib`** — добавить в комментарий в черновике или issue.
- Предлагать новые рисунки и TikZ-схемы; сохранять их в `figures/` с уникальным именем.
- Проверять орфографию, пунктуацию, согласованность внутри одного файла.
- Читать `main.tex` и другие черновики для понимания контекста, но не изменять их.

## 3. Что агент НЕ должен делать

- Не переписывать статью целиком за один присест.
- Не удалять существующие метки (`\label`, `\ref`, `\cite`) и не менять их имена.
- Не менять форматирование IEEEtran: шрифты, поля, отступы, класс документа.
- Не добавлять пакеты в преамбулу.
- Не редактировать `README.md` или `AGENTS.md` без разрешения координатора.
- Не создавать файлы вне `drafts/` и `figures/` (кроме временных, если это требуется для проверки).

---

## 4. Работа с рисунками

- Новые рисунки — только в `figures/`.
- Имя файла: `<автор>_<краткое-описание>.png` (например, `yura_isa88_tree.png`).
- Не перезаписывайте существующие `figures/*.png`, если только участник не попросил заменить **свой** рисунок.
- TikZ-диаграммы можно править внутри своего `.tex`, но не копировать их в чужие файлы.

---

## 5. Работа с библиографией

- `bib/links.bib` ведёт **Давид**.
- Если агент нашёл новый источник, он добавляет его **в комментарий** в конце соответствующего черновика или в issue в формате BibTeX.
- Формат BibTeX должен соответствовать существующим записям в `bib/links.bib`.

---

## 6. Работа с Git (если агент используется внутри Kimi Code / Claude с доступом к репозиторию)

- Коммитьте только изменения в своём `drafts/*.tex` и своих рисунках.
- Не пушьте напрямую в `main`.
- Сообщения коммитов: `<автор>: краткое описание` (например, `dima: rewrite neurocontrol intro`).
- Перед предложением merge убедитесь, что `main.tex` компилируется.

---

## 7. Проверка качества перед ответом человеку

Перед тем как вернуть результат участнику, агент должен убедиться:

1. Изменения касаются только разрешённого файла/рисунка.
2. Сохранён стиль IEEEtran.
3. Не удалены/изменены метки без необходимости.
4. Новые источники не внедрены в `bib/links.bib` без ведома Давида.
5. Текст действительно повышает оригинальность (переформулирован, сокращены шаблонные фрагменты).

---

## 8. Если агент не уверен

- Задайте уточняющий вопрос человеку.
- Не действуйте по принципу «лучше сделать, чем не сделать».
- Лучше сохранить черновик безопасным, чем сломать сборку или нарушить ограничения репозитория.
